AD sign-in

Whoever opens the app is signed in with their Windows account - with no typing (Windows sign-in), or with DOMAIN\username + their Windows password. With "Anyone with a Windows account" ticked and no AD group, a person with no account here gets one on their first sign-in, with the role below (Viewer unless you change it); give them another role in Accounts below. With an AD group, only its members get an account that way (out of the group = refused at the next sign-in). Untick both to let in only the AD accounts you add one by one: Add Account with Sign-in = AD, or "Use AD" on an existing account. The accounts with an app password keep working (one Admin stays among them in case AD is down).

Windows sign-in on the client PCs (no password)

A domain PC signs in with the Windows user who is logged on, with no typing, only when the browser trusts this server as an intranet site. Otherwise the browser asks for a username and password.

  1. Open the app at {{ sso.address }}. A name without dots is intranet by default. A full name with dots or an IP address makes the browser ask for a password.
  2. For every PC at once, IT sets the GPO Computer Configuration > Administrative Templates > Windows Components > Internet Explorer > Internet Control Panel > Security Page > Site to Zone Assignment List: {% for s in sso.zone_sites %}{{ s }} = 1{{ ', ' if not loop.last }}{% endfor %} (Edge and Chrome use the same list).
  3. For one PC only: download the .reg file and open it on that PC with the user who signs in (no admin rights needed), then restart the browser. It does nothing where the GPO "use only machine settings" is on.
  4. Optional, for Kerberos instead of NTLM when the server runs as a domain service account: {% for n in sso.names %}setspn -S HTTP/{{ n }} DOMAIN\service-account{{ ', ' if not loop.last }}{% endfor %}.
